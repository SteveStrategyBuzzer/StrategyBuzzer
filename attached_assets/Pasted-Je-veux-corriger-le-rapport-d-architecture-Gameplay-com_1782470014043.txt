Décisions finales :

1. Solo est la référence visuelle officielle.
Les écrans Solo existants servent de base visuelle.
Mais l’architecture ne doit pas être définie uniquement par le HTML actuel de Solo.
Elle doit être définie par les concepts gameplay communs.

2. Les 7 écrans universels officiels sont :

- question
- answer-reveal
- player-result
- round-end
- ultimate-participant-choice
- ultimate-player-choice
- match-end

Ne pas utiliser seulement “answer” et “result”.
“answer-reveal” = écran de révélation des réponses.
“player-result” = résultat de la question pour les joueurs.
“match-end” = fin de partie.

3. Manche Ultime est une phase spéciale avant le dernier cycle.

Ordre exact :

round-end
↓
ultimate-participant-choice
↓
ultimate-player-choice
↓
question
↓
answer-reveal
↓
player-result
↓
match-end

Manche Ultime n’est pas une variante de résultat.

- ultimate-participant-choice.blade.php
- ultimate-player-choice.blade.php

Chaque screen assemble seulement les composants communs.
Aucune logique gameplay dans les screens.

6. Créer une couche conceptuelle :

GameScreenRenderer

Rôle :
recevoir GAME_SCREEN_CONTEXT
déterminer le screenType
assembler le bon screen
afficher les bons composants
ne jamais calculer le score
ne jamais décider des phases
ne jamais remplacer Node

Flux cible :

GAME_SCREEN_CONTEXT
↓
GameScreenRenderer
↓
game/screens/{screenType}
↓
game/components/*

- gameMode
- matchType
- screenType
- phase

- timer

- question

- difficulty
- answers

- actions

- coins

Tous les modes alimentent ce même contrat.

8. Ce qui change selon le mode :

- source des données
- nombre de joueurs
- Socket.IO / Node
- bots
- actions disponibles
- contrôle MJ
- runtime utilisé

9. Ce qui ne doit pas changer :

- structure visuelle
- composants
- rendu question
- rendu réponses
- rendu résultat
- rendu fin de manche
- rendu fin de match
- rendu Manche Ultime
- animations de base
- CSS final

Exemple :
si un runtime lit #chronoTimer, #playerScore, #buzzContainer, ces IDs ne doivent pas disparaître sans adaptation validée.
