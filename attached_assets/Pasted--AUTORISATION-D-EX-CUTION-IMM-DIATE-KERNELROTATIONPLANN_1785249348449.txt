# 6. Tour de Depth

Implante les huit Domaines de création dans cet ordre :

```text
Géographie
→ Histoire
→ Faune
→ Art
→ Sport
→ Cinéma
→ Cuisine
→ Science
→ retour à Géographie
```

`Général` est interdit dans la création.

Au début d’un nouveau Tour de Depth :

```text
8 Domaines = ON
```

Lorsque Taxonomy fournit un territoire :

```text
Domaine reste ON
```

Lorsque Taxonomy retourne `EMPTY` :

```text
Domaine ON → OFF
```

Le Domaine devient non sélectionnable jusqu’au Tour de Depth suivant.

Un second `EMPTY` pour un Domaine déjà `OFF` doit être un `NO-OP`.

Aucun signal `AVAILABLE` ne doit exister.

---

# 7. DepthNeedMatrix

Implante :

```text
DepthCycle = [2, 4, 6, 7, 8, 9, 10]
```

Cibles :

```text
2  → 250 Tours
4  → 300 Tours
6  → 350 Tours
7  → 350 Tours
8  → 350 Tours
9  → 250 Tours
10 → 100 Tours
```

Implante :

```text
cycle_target[depth]
cycle_completed[depth]
empty_progress_current_tour
kernel_received_total[depth][domain]
```

Chaque nouvelle transition `ON → OFF` produit exactement :

```text
empty_progress_current_tour += 1
```

À `8/8` :

```text
cycle_completed[active_depth] += 1
```

Puis sélectionner le prochain Depth du cycle dont :

```text
cycle_completed[depth] < cycle_target[depth]
```

Après Depth 10, reprendre la recherche à Depth 2.

Ne recommence jamais immédiatement un nouveau Tour du même Depth.

# 10. EMPTY et réutilisation du Blueprint

Sur `EMPTY` :

1. conserver le même `blueprint_id` ;
2. passer le Domaine de `ON` à `OFF` ;
3. augmenter la progression ;
4. sélectionner le prochain Domaine `ON` ;
5. remplacer le couple provisoire `depth + domain` dans le même Blueprint ;
6. consulter Taxonomy de nouveau.

Ne crée aucun nouveau Blueprint après `EMPTY`.

Aucun `CURRENT_KERNEL_RECEIVED` ne doit être envoyé après `EMPTY`.

# 11. PRODUCTION_ON_HOLD

Lorsque tous les Depths ont atteint leur `cycle_target` :

```text
PRODUCTION_ON_HOLD
```

Le Blueprint déjà créé passe à :

```text
NOT_ENGAGED_PRODUCTION_ON_HOLD
```

Il :

* ne poursuit pas le pipeline ;
* ne va pas dans ReadyBank ;
* n’est pas comptabilisé ;
* reste uniquement comme trace technique ;
* ne bloque pas une relance future lorsque les besoins changent.

# 12. CURRENT_KERNEL_RECEIVED

Implante un événement transactionnel avec Outbox.

Payload obligatoire :

```text
event_id
event_type = CURRENT_KERNEL_RECEIVED
schema_version = 1
blueprint_id
depth
domain
occurred_at
```

ReadyBank doit écrire l’événement dans la même transaction que la réception canonique du Blueprint.

Crée un listener :

```text
ApplyCurrentKernelReceivedToRotation
```

Le listener doit :

1. vérifier `blueprint_id` ;
2. créer un reçu idempotent ;
3. ne rien incrémenter si le reçu existe déjà ;
4. sinon incrémenter :

```text
kernel_received_total[depth][domain] += 1
```

5. autoriser la création du Blueprint suivant ;
6. marquer l’événement Outbox comme traité.
