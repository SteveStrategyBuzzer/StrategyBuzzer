==================================================
CORRECTION B — PRODUCTION_ON_HOLD N'EST PAS UN ÉTAT BLUEPRINT
==================================================

L'état :

NOT_ENGAGED_PRODUCTION_ON_HOLD

actuellement présent dans kernel_blueprint_runs.execution_state
est une trace de l'ancienne architecture.

Dans KRP v3.2 :

PRODUCTION_ON_HOLD
=
état de production/rotation KRP.

Il ne doit PAS devenir :

kernel_blueprint_runs.execution_state = PRODUCTION_ON_HOLD.

En état terminal :

aucun Blueprint n'est créé.

Donc aucun Blueprint ne doit avoir besoin d'être marqué
PRODUCTION_ON_HOLD.

Le plan doit identifier :

- tous les writers de NOT_ENGAGED_PRODUCTION_ON_HOLD ;
- tous les readers ;
- les tests associés ;
- les éventuelles données historiques existantes ;
- comment retirer le chemin actif sans violer 01_KernelBlueprint verrouillé.

Ne modifie PAS la spécification 01_KernelBlueprint.
