===========================================================
CORRECTION 1
Le Bassin Taxonomy ne produit PAS un noyau.
===========================================================

Le Bassin Taxonomy produit uniquement une cartouche candidate.

Cette cartouche contient uniquement :

- depth
- domain_code
- sub_domain
- subject
- dominant_idea
- knowledge_frequency

Le noyau n'existe pas encore à cette étape.

Le noyau est construit progressivement dans le KernelBlueprint.

Modifier le vocabulaire partout dans le document.

Remplacer :

"le Bassin produit un noyau"

par

"le Bassin produit une cartouche candidate."

===========================================================
CORRECTION 2
Le KernelBlueprint devient le support vivant du pipeline.
===========================================================

Le KernelBlueprint n'est pas uniquement créé au début.

Il accompagne toute la chaîne de création.

Chaque brique remplit uniquement les slots dont elle est propriétaire.

Le Blueprint est la structure commune qui circule dans tout le pipeline.

Bassin Taxonomy

↓

Le Bassin est le moteur Taxonomy.

Il contient, pour un depth donné,
les huit domaines Gameplay.

Chaque domaine possède deux chargeurs autonomes :

Chargeur de sujets

↓

Sous-domaine actif

↓

jusqu'à 50 sujets

Chargeur d'idées

↓

Sujet actif

↓

5 idées dominantes

Les huit domaines avancent de manière autonome.

Ils sont coordonnés exclusivement
par KernelRotationPlanner.

Le Bassin ne crée jamais un noyau.

Il produit uniquement une cartouche candidate.

Il remplit uniquement les slots Blueprint suivants :

- sub_domain
- subject
- dominant_idea
- knowledge_frequency
