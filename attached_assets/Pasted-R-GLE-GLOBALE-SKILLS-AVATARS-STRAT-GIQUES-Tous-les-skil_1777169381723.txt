RÈGLE GLOBALE SKILLS / AVATARS STRATÉGIQUES

Tous les skills doivent être visibles au minimum sur la page Question pour indiquer clairement :
- skill disponible
- skill actif
- skill consommé
- skill bloqué / non applicable

Ensuite, chaque skill doit être activable ou affiché sur la bonne page selon son effet réel.

Aucun skill ne doit être câblé uniquement dans une Blade isolée.
Les effets doivent passer par le runtime commun :
- activeEffects
- skill_used
- skill_activated
- restoreState
- GameEffectsRuntime / GameplayRuntime

Node reste autorité.
Le client affiche seulement l’effet reçu ou autorisé.

VALIDATION SKILLS OBLIGATOIRE

Pour chaque skill, Replit doit vérifier :
- page où il est visible
- page où il est activable
- event Socket utilisé
- effet Node correspondant
- activeEffects mis à jour
- affichage après reconnect / restoreState
- état disponible/actif/consommé
- compatibilité Duo
- compatibilité Solo
- compatibilité Maître du jeu
- compatibilité Ligue

INTERDICTION

Ne pas coder un skill directement dans une page isolée si ce skill doit exister dans plusieurs modes.

Toute logique réutilisable doit aller dans :
- Node / GameOrchestrator pour la vérité gameplay
- GameEffectsRuntime ou GameplayRuntime pour l’affichage commun
- Blade seulement pour les hooks DOM et l’état visuel passif. 

Oui, les skills doivent être compatibles Solo, mais Solo peut garder une exécution différente.
Règle propre :
Même contrat de skill pour tous les modes.
Exécution adaptée selon le mode.
Donc :
Duo / Master / Ligue : skills passent par Node, car ils peuvent affecter d’autres joueurs.
Solo : skills peuvent rester locaux/privés si ça touche seulement le joueur ou les bots, mais ils doivent respecter le même contrat :
même nom de skill
même phase autorisée
même compteur d’utilisation
même effet logique
mêmes stats finales si applicable
Exemple :
Scientifique
- Solo : élimine une mauvaise réponse localement.
- Duo : Node décide quelle mauvaise réponse est éliminée et envoie l’effet.
Explorateur
- Solo : montre le choix d’un bot système.
- Duo : montre le choix adverse réel.
- Master : montre la réponse la plus cliquée.
Donc Solo ne doit pas être un monde séparé avec ses propres règles inventées.
Verdict :
Solo peut être local pour l’UX.
Mais Solo ne doit pas être indépendant du modèle central.
Sinon on va recrée exactement les problèmes qu’on veut supprimer : un jeu par mode.
