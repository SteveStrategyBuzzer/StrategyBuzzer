OBJECTIF — INTÉGRER LA LOGIQUE GAMEPLAY DE CONSOMMATION DES COGNITIFS

Architecture cible verrouillée :

READY_BANK = banque de NOYAUX MÈRES ENCODÉS.
GAMEPLAY ne consomme pas un noyau complet.
GAMEPLAY consomme des cognitifs VALIDATED_OK à l’intérieur d’un noyau.

Le noyau reste l’unité centrale.
Le cognitif est l’unité consommée.

────────────────────────
3. FONCTIONS MÉCANIQUES À INTÉGRER
────────────────────────

Créer ou intégrer l’équivalent de :

getAvailableKernels(player_id, depth, domain)
- retourne les NOYAUX MÈRES ENCODÉS de READY_BANK pour depth + domain.

classifyKernelForPlayer(player_id, kernel_id)
- retourne :
  VIERGE
  TOUCHÉ
  BACK_SUPPORT

getConsumedCognitives(player_id, kernel_id)
- retourne les cognitifs déjà joués par ce joueur dans ce noyau.

getAvailableCognitives(player_id, kernel_id)
- prend les cognitifs VALIDATED_OK du noyau
- retire ceux déjà consommés par le joueur.

chooseNextCognitive(player_id, kernel_id)
Priorité :
1. Recognition non consommée
2. Reasoning non consommée
3. Deceptive Trap non consommé
4. formes restantes si nécessaire

markCognitiveConsumed(player_id, kernel_id, cognitive_key, match_id, result)
- écrit l’historique dès qu’un cognitif est joué.

updateKernelPlayerStatus(player_id, kernel_id)
- VIERGE si aucun cognitif consommé
- TOUCHÉ si au moins un cognitif consommé
- BACK_SUPPORT si Recognition + Reasoning + Deceptive Trap consommés

────────────────────────
5. RÈGLES DE CONSOMMATION
────────────────────────

Un cognitif est consommé si :

player_id + kernel_id + cognitive_key existe dans l’historique.

Une famille est consommée si :

player_id + kernel_id + cognitive_family existe dans l’historique.

Un noyau est TOUCHÉ si :

au moins un cognitif de ce noyau a été consommé.

Un noyau est BACK_SUPPORT si :

Recognition consommée
+
Reasoning consommée
+
Deceptive Trap consommé

BACK_SUPPORT ne veut pas dire noyau épuisé.
BACK_SUPPORT veut dire :
le joueur a vécu l’expérience pédagogique minimale du noyau.

────────────────────────
6. PRIORITÉ DE SÉLECTION GAMEPLAY
────────────────────────

Quand Gameplay reçoit depth + domain :

1. chercher les noyaux VIERGES
2. sinon chercher les noyaux TOUCHÉS avec cognitifs disponibles
3. sinon utiliser BACK_SUPPORT

Ne pas choisir au hasard avant d’avoir appliqué cette priorité.

Le hasard peut rester seulement comme tie-breaker entre plusieurs choix équivalents.

────────────────────────
7. CONTRAINTES IMPORTANTES
────────────────────────

Ne pas transformer READY_BANK en banque de cognitifs.

READY_BANK stocke des NOYAUX MÈRES ENCODÉS.

Gameplay expose/consomme les cognitifs VALIDATED_OK à l’intérieur du noyau.

Ne pas casser :
- Solo
- Duo
- MJ
- Ligue

Le suivi doit être compatible multi-mode.
