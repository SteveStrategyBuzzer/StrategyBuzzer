Dans F12 VM, on voit :
VALIDATION_ERROR: Invalid join_room payload

Diagnostic confirmé :
- JoinRoomSchema Node exige :
  roomId optional
  lobbyCode optional
  playerId required
  playerName required
  avatarId optional
  strategicAvatarId optional
  color optional
  division optional
  token optional

- DuoSocketClient envoie :
  roomId, lobbyCode, playerId, playerName, avatarId, strategicAvatarId, division, token

Donc le schéma et le payload client sont compatibles.

Cause probable confirmée :
GameplayRuntime.js construit joinPayload avec :
  playerId: USER_ID || ''
  token: JWT_TOKEN
  Object.assign(..., PLAYER_INFO)
  if (PLAYER_NAME) joinPayload.playerName = PLAYER_NAME

Mais les pages Duo gameplay injectent :
  CURRENT_USER_ID ✅
  USER_ID ❌
  PLAYER_NAME ❌
  PLAYER_INFO ❌

Seul lobby.blade.php injecte PLAYER_NAME et PLAYER_INFO.

Donc le payload join_room peut partir avec playerId/playerName vide sur les pages gameplay.
