8 — STRUCTURE OFFICIELLE DU KERNEL_CODE

Format :

DD-DO-SUB-SUJ-IDE-VVVV

où :

DD
= Depth sur exactement 2 caractères

DO
= code Domaine sur exactement 2 caractères

SUB
= 3 caractères issus du Sous-domaine

SUJ
= 3 caractères issus du Sujet

IDE
= 3 caractères issus de l’Idée Dominante

VVVV
= suffixe séquentiel base36 sur exactement 4 caractères

Exemple :

04-GE-CAN-CON-ACT-0000

Longueur totale :

2 + 1
+ 2 + 1
+ 3 + 1
+ 3 + 1
+ 3 + 1
+ 4
= 22 caractères

Regex structurelle :

^[0-9]{2}-[A-Z]{2}-[A-Z0-9]{3}-[A-Z0-9]{3}-[A-Z0-9]{3}-[0-9A-Z]{4}$

Le kernel_code est toujours :

UPPERCASE
ASCII
sans espace
sans accent
sans caractère libre

Le point le plus important que ce contrat fixe est que le suffixe VVVV devient un compteur d’identité persistant par bassin Depth + Domaine, et non plus l’ancien mécanisme ambigu de collision KLD/KS.

Donc, pour un bassin comme 04-GE :

04-GE-...-0000
04-GE-...-0001
...
04-GE-...-ZZZZ

et 04-HI, 06-GE, etc. possèdent chacun leur propre espace indépendant de 1 679 616 identités.
