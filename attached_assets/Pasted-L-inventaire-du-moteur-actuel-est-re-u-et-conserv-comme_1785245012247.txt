# 6. Architecture à intégrer dans la nouvelle spécification

## KernelBlueprint

* créé avant KernelRotationPlanner ;
* reçu par KRP ;
* KRP ne crée pas l’enveloppe ;
* KRP écrit seulement :

  * depth ;
  * domain.

## Tour de Depth

Au début de chaque Tour de Depth :

* Géographie = ON ;
* Histoire = ON ;
* Faune = ON ;
* Art = ON ;
* Sport = ON ;
* Cinéma = ON ;
* Cuisine = ON ;
* Science = ON.

Général est exclu.

Taxonomy ne transmet pas `AVAILABLE`.

Territoire fourni :

* Domaine reste ON ;
* Blueprint poursuit le pipeline.

EMPTY :

* Domaine ON → OFF ;
* Domaine OFF ignoré pour le reste du tour ;
* une seule transition comptabilisable par Domaine ;
* même Blueprint conservé ;
* prochain Domaine ON sélectionné immédiatement.

## DepthNeedMatrix

Elle porte :

* DepthCycle :
  `2 → 4 → 6 → 7 → 8 → 9 → 10` ;
* `cycle_target[depth]` ;
* `cycle_completed[depth]` ;
* progression :
  `0/8 → 1/8 → … → 8/8` ;
* `kernel_received_total[depth][domain]`.

Elle ne porte pas :

* les identités des Domaines ON/OFF ;
* une table AVAILABLE/EMPTY ;
* une liste parallèle des Domaines exclus ;
* `kernel_received_total[depth]` comme compteur stocké séparément.

Chaque nouveau passage ON → OFF :

`progression +1/8`

À 8/8 :

`cycle_completed[active_depth] += 1`

Puis recherche du prochain Depth encore sous sa cible.

Après Depth 10, la recherche reprend à Depth 2.

## KernelRotationPlanner

* utilise Tour de Depth ;
* utilise DepthNeedMatrix ;
* conserve le même active_depth tant que moins de huit Domaines sont OFF ;
* sélectionne le prochain Domaine ON ;
* inscrit depth + domain ;
* applique le changement de Depth à 8/8.

## Taxonomy

Taxonomy fournit :

* subdomain_active ;
* subject_active ;
* dominant_idea_active ;

ou :

* EMPTY.

Aucun signal AVAILABLE.

## ReadyBank

CURRENT_KERNEL_RECEIVED :

* confirme la réception du Blueprint ;
* permet la comptabilisation idempotente :
  `kernel_received_total[depth][domain] += 1` ;
* autorise la création du Blueprint suivant ;
* autorise la prochaine itération KRP.
